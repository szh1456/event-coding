## 5. Deviations and incidents

1. **`find_annotation`** (Section 4) now returns `ann_dir / <stem>_bbox.npy`, and
   raises if that file does not exist. Nothing is searched. Its test in
   `tests/test_annotations.py`, which is not a gate, now passes the train
   subdirectory and checks that the function does not search below the directory it
   is given. No directory under the annotation root was listed during this
   directive. Annotation paths are built from `docs/DATA.md`'s train subdirectory
   (`ec/mp.py`).
2. **Shards and event slices.** Stage R runs one task per shard of directive 001, on
   the same tracks. Each task keeps the events of `[min t_first, max t_last]` of its
   tracks. `evaluate_regen` returns `outside_track_life` before reading any event when
   a window leaves the track's life, so the results are unchanged. Acceptance checks 4
   and 6 (exact `n_future`, exact reproduction of directive 001) confirm it.
3. **Read slots and CPU accounting.** At most 3 tasks read a recording at once, to
   bound memory. Tasks wait for a slot, so the sums of task wall times (32.2 h and
   22.3 h) overstate the CPU used. The time inside the reference functions was
   4.19 h and 7.36 h. The reads were 700 + 487 full-file reads. Wall time was set
   by the read slots, not by the cores.
4. **Choices where the directive is silent**, fixed before any Stage R or Stage B
   number:
   - The share of rows with `b_px` at 4 px is a mean over a recording's rows,
     then the median over recordings, as the shares were in report 001. The pooled
     share is reported next to it.
   - In the fixed-bandwidth gain, `N` is `n_future` of the B6 run, which equals that
     of the B4 run and of directive 001.
   - Table 5 reports the quantities of Table 1. Table 6 counts the Stage R rows of
     each lead, which are the rows directive 001 scored.
   - The Stage B quantities are aggregated in stratum H only, since every subsampled
     row is in H.
5. **The probe rows** (50 of each stage, `~/prjs/event_coding/rg/probe_*`) only
   project the cost. They are not part of the results.
6. **Reference ledger.** No external source was used. `docs/REFERENCE_LEDGER.md` is
   unchanged.

## 6. Questions for the director

1. **`static` is still censored under B6.** It sits at 4 px in 82% (day) and 67%
   (night) of the rows, its fixed-bandwidth gain still rises from 2 to 4 px, and its
   `eps` falls to 0.004 / 0.011. `Delta(B6)` (1.55 / 1.29 bits) is therefore still an
   upper bound on the lossless saving of explicit motion. With D-002-1 closing the
   lossless track this does not affect a decision. Should the paper quote it as an
   upper bound, or should a later directive extend the set further on the same
   subsample?
2. **The lead degrades regeneration faster than predicted.** `F1(cmax)` at D = 300 ms
   is 0.41 to 0.42 of its D = 0 value, against a predicted 0.5 to 0.9. At 100 ms it
   is 0.72 to 0.76. A refreshed template, as Section 14 describes, would bound the
   lead the codec has to bridge. Should the codec directive set its refresh period
   from Table 3?
3. **Slow objects.** For vehicles under 20 px/s, `G` is 0 and `F1(cmax)` is only 0.31
   (day) and 0.46 (night). There, repetition is as good as motion and both are poor.
   Should the codec treat that speed bin by another mode, for example coding the
   events directly?
